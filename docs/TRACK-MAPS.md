# Track maps in the events section

Every event on the [schedule](https://danieloliverracing.com/schedule) — and every track-tagged news
post — can show the **circuit's outline**, drawn as a gradient line, next to the country flag.

![Event card with circuit outline](screenshots/trackmap-card.webp)

The outline in the corner is the real shape of the circuit (here, Circuit of the Americas), projected
from GPS coordinates to an SVG path. This guide covers how an event gets its map, how the outlines are
drawn, and how to add or regenerate them.

---

## What an event shows

Events live in [`src/content/events/*.md`](../src/content/events) and carry an optional **`track`**
id:

```yaml
---
title: "IMSA Airbnb Endurance Challenge — Circuit of the Americas"
circuit: "Circuit of the Americas"   # free-text fallback label
location: "Austin, TX"
series: "IMSA VP Racing SportsCar Challenge"
track: "cota"                        # ← id into src/data/tracks.json
status: "completed"
---
```

That `track` id is picked from a **dropdown in the CMS** (populated from the 222-circuit list), so
editors never type it by hand. On the schedule page, [`schedule.astro`](../src/pages/schedule.astro)
resolves it with `trackById()` and renders three things from the matched record:

- the **circuit name** (falling back to the free-text `circuit` field if no id is set),
- the **country flag** ([`Flag.astro`](../src/components/Flag.astro), an SVG so it renders on every OS),
- the **circuit outline** ([`TrackMap.astro`](../src/components/TrackMap.astro)) as a corner overlay.

If the track has no drawn outline, `TrackMap` simply renders nothing — the flag and name still show.

## How the outline is drawn

Each circuit record in [`src/data/tracks.json`](../src/data/tracks.json) looks like this — the shape
lives entirely in `path` + `viewBox`:

```json
{ "id": "cota", "name": "Circuit of the Americas", "country": "United States",
  "flag": "🇺🇸", "iso": "us", "viewBox": "0 0 100 100", "path": "M52 12 L…Z" }
```

`TrackMap.astro` just strokes that path with the site's pink→violet→cyan gradient:

```astro
<svg viewBox={track.viewBox} fill="none">
  <path d={track.path} stroke="url(#gradient)" stroke-width="2"
        stroke-linecap="round" stroke-linejoin="round" />
</svg>
```

The `path` is generated by [`scripts/build-tracks.mjs`](../scripts/build-tracks.mjs), which turns a
list of `{ lat, lon }` GPS points tracing the circuit into a normalized SVG path:

1. **Project lat/lon → flat x/y.** An equirectangular projection: `x = lon × cos(meanLatitude)` (the
   cosine corrects for longitude lines bunching together away from the equator) and `y = −lat` (screen
   y grows downward/south). At circuit scale this is accurate to well within a pixel.
2. **Normalize into a 100×100 box.** Take the bounding box of the projected points, scale uniformly to
   fit a `0 0 100 100` viewBox with a small pad, and centre it on the shorter axis — so every circuit
   is drawn at a consistent size regardless of its real-world dimensions or where on Earth it is.
3. **Emit the path.** Round to 0.1 and join the points as `M x y  L x y  …  Z` (a closed loop).

Only circuits with more than a handful of points get a map; the rest still resolve for name + flag.

## Adding or regenerating maps

`src/data/tracks.json` is **committed and already holds 222 circuits**, so most events just need the
right `track` id — nothing to build.

To add a circuit or fix a shape, add a coordinate trace and re-run the projection. `build-tracks.mjs`
reads its source list + outlines from a separate data repo (a personal path at the top of the script —
point it at your own coordinate source). Then:

```bash
node scripts/build-tracks.mjs      # rewrites src/data/tracks.json
```

Or, for a one-off, **hand-add a record**: give it an `id`, `name`, `country`, and `iso` (ISO-3166
alpha-2, lowercase — drives the flag image at `public/images/flags/<iso>.svg`). Add `viewBox` +
`path` if you want the outline; the record works without them (name + flag only). To turn a set of GPS
points into a `path`, apply the same three steps above — the projection math is the ~15 lines in
`outlineToPath()` inside `build-tracks.mjs`, reusable on any `{ lat, lon }[]`.
